### Security & Authentication in TypeScript

#### Core Concept and Significance

Security and authentication are critical components of modern web applications. They ensure that user data is protected and that users are who they claim to be.

- **Authentication** verifies the identity of users (e.g., through usernames and passwords).
- **Authorization** determines what authenticated users are allowed to do.

In TypeScript, implementing these security measures helps safeguard applications against unauthorized access and various security threats.

### Implementing Security Practices for Backend Systems

#### 1. JWT for Authentication

**JSON Web Tokens (JWT)** are a compact and self-contained way for securely transmitting information between parties as a JSON object. They are commonly used for authentication in web applications.

**Code Example: Using JWT for Authentication in TypeScript**

```typescript
import jwt from 'jsonwebtoken';

const SECRET_KEY = 'your_secret_key';

/**
 * Generates a JSON Web Token for a given user ID.
 *
 * @param {string} userId - The ID of the user to generate a token for.
 * @returns {string} The generated JWT.
 */
function generateToken(userId: string): string {
  const token = jwt.sign({ id: userId }, SECRET_KEY, { expiresIn: '1h' });
  return token;
}

/**
 * Verifies the provided JWT and returns the decoded payload.
 *
 * @param {string} token - The JWT to verify.
 * @returns {object | null} The decoded payload or null if invalid.
 */
function verifyToken(token: string): object | null {
  try {
    const decoded = jwt.verify(token, SECRET_KEY);
    return decoded;
  } catch (error) {
    console.error('Invalid token:', error);
    return null;
  }
}

// Example Usage
const userId = '12345';
const token = generateToken(userId);
console.log('Generated JWT:', token);

const decoded = verifyToken(token);
console.log('Decoded payload:', decoded);
```

**Explanation:**

- `generateToken` function creates a JWT for a user based on their ID and a secret key.
- `verifyToken` function checks if the JWT is valid and returns the decoded payload. If invalid, it logs an error and returns `null`.

#### 2. OAuth

**OAuth** is an open standard for access delegation commonly used for token-based authentication and authorization. It allows users to grant third-party applications access to their resources without sharing their passwords.

**Code Example: Setting Up OAuth with TypeScript**

```typescript
import express from 'express';
import passport from 'passport';
import { Strategy as GoogleStrategy } from 'passport-google-oauth20';

const app = express();

// Configure Passport to use Google OAuth
passport.use(
  new GoogleStrategy(
    {
      clientID: 'your_google_client_id',
      clientSecret: 'your_google_client_secret',
      callbackURL: '/auth/google/callback',
    },
    (accessToken, refreshToken, profile, done) => {
      // Save the user profile in the session or database
      return done(null, profile);
    }
  )
);

app.get(
  '/auth/google',
  passport.authenticate('google', { scope: ['profile', 'email'] })
);

app.get(
  '/auth/google/callback',
  passport.authenticate('google', { failureRedirect: '/' }),
  (req, res) => {
    // Successful authentication, redirect home.
    res.redirect('/');
  }
);

// Example usage: Start server
app.listen(3000, () => {
  console.log('Server running on http://localhost:3000');
});
```

**Explanation:**

- This code uses the Google OAuth strategy to authenticate users.
- The `/auth/google` route redirects users to Google's login page, while `/auth/google/callback` handles the response from Google.

#### 3. Securing APIs with Rate Limiting and Encryption

**Rate Limiting** helps protect APIs from abuse and denial-of-service attacks by limiting the number of requests a user can make in a given timeframe.

**Code Example: Rate Limiting in TypeScript**

```typescript
import express from 'express';
import rateLimit from 'express-rate-limit';

const app = express();

// Apply rate limiting to all requests
const limiter = rateLimit({
  windowMs: 15 * 60 * 1000, // 15 minutes
  max: 100, // Limit each IP to 100 requests per windowMs
});

app.use(limiter);

// Example route
app.get('/api', (req, res) => {
  res.send('Hello, this is a secure API!');
});

// Start server
app.listen(3000, () => {
  console.log('Server running on http://localhost:3000');
});
```

**Explanation:**

- This code implements a basic rate limiter that allows 100 requests per 15 minutes from a single IP.

**Encryption** is crucial for securing sensitive data. Use libraries like `crypto` for encryption in Node.js.

**Code Example: Encrypting Data**

```typescript
import crypto from 'crypto';

/**
 * Encrypts a given text using AES-256-CBC algorithm.
 *
 * @param {string} text - The text to encrypt.
 * @returns {string} The encrypted text in base64.
 */
function encrypt(text: string): string {
  const algorithm = 'aes-256-cbc';
  const key = crypto.randomBytes(32);
  const iv = crypto.randomBytes(16);

  const cipher = crypto.createCipheriv(algorithm, Buffer.from(key), iv);
  let encrypted = cipher.update(text, 'utf8', 'base64');
  encrypted += cipher.final('base64');

  return `${iv.toString('base64')}:${encrypted}`;
}

// Example usage
const secretMessage = 'This is a secret!';
const encryptedMessage = encrypt(secretMessage);
console.log('Encrypted message:', encryptedMessage);
```

**Explanation:**

- The `encrypt` function uses the AES-256-CBC algorithm to encrypt text and returns the IV and encrypted text as a base64 string.

### TypeScript Built-in Support

TypeScript does not have specific built-in support for security and authentication but enhances type safety and development experience when implementing security features. For instance, you can define types for tokens or user profiles to avoid errors during development.

### Practical Use Case

Consider a web application that allows users to log in using Google OAuth. After logging in, users can access secure resources (e.g., their profiles or sensitive data) that require a JWT for authentication. Rate limiting protects the API from abusive requests, ensuring the application remains responsive.

### Common Mistakes and Best Practices

- **Storing Secrets:** Avoid hardcoding secret keys in your code. Use environment variables or secret management tools.
- **Token Expiration:** Ensure that JWTs have a short expiration time and refresh them as needed.
- **Input Validation:** Always validate and sanitize user inputs to prevent attacks like SQL injection or XSS.
- **Using HTTPS:** Always serve your application over HTTPS to encrypt data in transit.
