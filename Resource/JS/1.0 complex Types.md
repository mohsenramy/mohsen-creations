In TypeScript, **complex types** often involve combining or creating more advanced data structures using **unions**, **intersections**, and other type manipulation techniques. These complex types can combine **objects**, **primitives**, and **functions** to express more flexible and sophisticated type definitions.

### 1. **Union Types**

A **union type** allows a variable to hold values of multiple types. It represents a type that can be **one of several types** (e.g., either a string, number, object, or even a function). This is extremely useful for handling flexible data structures where a variable can have more than one possible type.

#### Example of a Union of Primitives

```typescript
// A variable can either be a number or a string
type ID = number | string;

/**
 * Function that accepts either a number or a string as ID.
 * @param {ID} id - The unique identifier, either as a number or a string
 */
function printId(id: ID) {
  if (typeof id === 'string') {
    console.log(`ID as string: ${id.toUpperCase()}`);
  } else {
    console.log(`ID as number: ${id}`);
  }
}

printId(123); // ID as number: 123
printId('abc'); // ID as string: ABC
```

In this example, the `ID` type can be either a `number` or a `string`. The function checks the type of the input and handles it accordingly.

#### Example of a Union of Objects

```typescript
// Defining two distinct types
type Dog = {
  breed: string;
  bark: () => string;
};

type Cat = {
  breed: string;
  meow: () => string;
};

// Union of Dog and Cat
type Pet = Dog | Cat;

/**
 * Function to describe a pet based on its type (Dog or Cat)
 * @param {Pet} pet - The pet object, which can be either a Dog or Cat
 */
function describePet(pet: Pet) {
  console.log(`Breed: ${pet.breed}`);

  // Use type narrowing to call specific methods
  if ('bark' in pet) {
    console.log(pet.bark()); // This is a dog
  } else {
    console.log(pet.meow()); // This is a cat
  }
}

const myDog: Dog = {
  breed: 'Golden Retriever',
  bark: () => 'Woof!',
};

const myCat: Cat = {
  breed: 'Siamese',
  meow: () => 'Meow!',
};

describePet(myDog); // Woof!
describePet(myCat); // Meow!
```

Here, the `Pet` type is a **union of objects** (`Dog` or `Cat`), and the function `describePet()` uses **type narrowing** (`"bark" in pet`) to handle each case correctly.

### 2. **Intersection Types**

An **intersection type** combines multiple types into one. The resulting type must satisfy **all** the combined types. This is particularly useful when you need to merge different interfaces or types into one.

#### Example of an Intersection of Objects

```typescript
// Defining two object types
type User = {
  name: string;
  email: string;
};

type Admin = {
  adminLevel: number;
};

// Intersection of User and Admin types
type SuperUser = User & Admin;

/**
 * Function that describes a super user
 * @param {SuperUser} superUser - A user who also has admin privileges
 */
function describeSuperUser(superUser: SuperUser) {
  console.log(
    `${superUser.name} (${superUser.email}) is an Admin Level ${superUser.adminLevel}.`
  );
}

const adminUser: SuperUser = {
  name: 'Alice',
  email: 'alice@example.com',
  adminLevel: 2,
};

describeSuperUser(adminUser); // Alice (alice@example.com) is an Admin Level 2.
```

In this case, the `SuperUser` type is an **intersection** of `User` and `Admin`, meaning an object must have properties from both types.

### 3. **Union of Functions**

A union of functions allows a value to be one of multiple function types. This is useful in scenarios where you want to handle multiple possible function signatures.

#### Example of a Union of Functions

```typescript
// Defining two possible function types
type StringTransformer = (input: string) => string;
type NumberTransformer = (input: number) => number;

// Union of the two function types
type Transformer = StringTransformer | NumberTransformer;

/**
 * Function that applies a transformer function to an input
 * @param {Transformer} transformer - The transformer function
 * @param {string | number} input - The input to transform, either a string or number
 */
function applyTransformer(transformer: Transformer, input: string | number) {
  if (typeof input === 'string' && typeof transformer === 'function') {
    console.log(transformer(input));
  } else if (typeof input === 'number' && typeof transformer === 'function') {
    console.log(transformer(input));
  }
}

// String transformer
const toUpperCase: StringTransformer = (input: string) => input.toUpperCase();

// Number transformer
const square: NumberTransformer = (input: number) => input * input;

applyTransformer(toUpperCase, 'hello'); // HELLO
applyTransformer(square, 5); // 25
```

Here, `Transformer` is a **union of function types**. Depending on the type of input, the appropriate transformer function is applied.

### 4. **Union of Objects and Primitives**

A **union of objects and primitives** allows for flexible types where a value could be either a complex object or a simple primitive type like `string` or `number`.

#### Example of a Union of Objects and Primitives

```typescript
// Union of primitive and object types
type Response = string | { success: boolean; message: string };

/**
 * Function that handles different types of responses
 * @param {Response} response - The response, which can be a string or an object
 */
function handleResponse(response: Response) {
  if (typeof response === 'string') {
    console.log(`Response: ${response}`);
  } else {
    console.log(`Success: ${response.success}, Message: ${response.message}`);
  }
}

// Example usage
handleResponse('Operation completed successfully.'); // Response: Operation completed successfully.
handleResponse({ success: true, message: 'Data saved!' }); // Success: true, Message: Data saved!
```

This demonstrates how you can have a type that is **either a primitive** (`string`) or **an object**. The `handleResponse()` function uses type narrowing to distinguish between them.

### 5. **Best Practices with Complex Types**

- **Use Type Narrowing**: Always ensure that you narrow down types (e.g., using `typeof`, `in`, or `instanceof`) when working with union types to correctly access properties or methods.
- **Prefer Union for Flexibility**: Union types are great when you expect different data forms (e.g., strings or objects) or function signatures.
- **Intersection for Combining**: Use intersection types when you need to combine multiple types into one and ensure that the resulting type includes all properties from the combined types.
- **Explicit Type Guards**: When using complex types, always include checks or guards to handle each case (e.g., `if (typeof value === "string")`).

---

### Conclusion

- **Union Types**: Allow for flexibility by combining multiple possible types (primitives, objects, or functions). Use them when a value can be one of many types.
- **Intersection Types**: Combine multiple types, where the result must satisfy all combined types. Use this for merging or composing types.

Both union and intersection types are powerful tools in TypeScript that let you write highly flexible and strongly-typed code, improving both safety and readability.
