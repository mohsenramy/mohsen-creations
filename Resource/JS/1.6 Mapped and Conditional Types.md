# Mapped & Conditional Types in TypeScript

## 1. Core Concept and Significance

Mapped Types in TypeScript allow you to create new types by transforming the properties of an existing type. By iterating over the keys of a given type, you can apply transformations or make adjustments to each property, enabling a highly flexible way to construct new types.

Conditional Types allow you to define types based on conditions. Using a ternary operator syntax, you can create types that resolve to different outcomes depending on whether a certain condition holds true. This is particularly useful for creating types that adapt based on the types they receive as parameters, enabling more dynamic and reusable type definitions.

### Why Mapped & Conditional Types Are Important:

- Type Transformation: Mapped types provide the ability to apply changes to all properties of a type, making it easy to apply modifications across an entire structure.
- Conditional Logic: Conditional types allow for conditional type declarations, making it possible to build types that change based on the input types, improving flexibility.
- Code Reusability and Consistency: Both mapped and conditional types reduce redundancy and make it easier to enforce consistency across types, leading to better maintainability.

## 2. Code Examples

### Example 1: Mapped Types

```typescript
// Define a basic interface
interface User {
  name: string;
  age: number;
  email: string;
}

// Create a Readonly version of User using Mapped Types
type ReadonlyUser = {
  readonly [K in keyof User]: User[K];
};

// Now all properties in ReadonlyUser are read-only
const readonlyUser: ReadonlyUser = {
  name: 'Alice',
  age: 30,
  email: 'alice@example.com',
};
// readonlyUser.age = 31; // Error: Cannot assign to 'age' because it is a read-only property
```

In this example, ReadonlyUser is a mapped type that iterates over all keys in the User type (keyof User) and makes them readonly.

### Example 2: Conditional Types

```typescript
// Define a conditional type that checks if a type is a string
type IsString<T> = T extends string
  ? "Yes, it's a string"
  : "No, it's not a string";

// Test with different types
type Test1 = IsString<string>; // "Yes, it's a string"
type Test2 = IsString<number>; // "No, it's not a string"
```

Here, IsString is a conditional type that evaluates to "Yes, it's a string" if the type T is a string, otherwise it evaluates to "No, it's not a string".

### Example 3: Combining Mapped and Conditional Types

```typescript
// Define a mapped type that makes properties optional only if they are of type string
type OptionalIfString<T> = {
  [K in keyof T]: T[K] extends string ? T[K] | undefined : T[K];
};

// Applying the mapped and conditional type on an interface
interface Profile {
  username: string;
  age: number;
}

type ProfileWithOptionalStrings = OptionalIfString<Profile>;

const profile: ProfileWithOptionalStrings = { age: 25 }; // valid because username can be undefined
```

In this example, OptionalIfString uses a mapped type to iterate over each property in T and applies a conditional check to make properties of type string optional.

## 3. Practical Use Case

### Use Case: API Response Transformation

When dealing with API responses, it’s common to receive data in a format that doesn’t align perfectly with your application’s requirements. Mapped types can help transform this data. For example, you could use mapped types to convert all properties of a response object to readonly or make properties optional based on specific conditions.

```typescript
interface ApiResponse {
  id: string;
  createdAt: string;
  updatedAt: string;
  data: string;
}

type OptionalApiResponse<T> = {
  [K in keyof T]: T[K] | undefined;
};

// Apply OptionalApiResponse to make all properties optional
type PartialResponse = OptionalApiResponse<ApiResponse>;

const response: PartialResponse = { id: '123' }; // valid, other fields are optional
```

Here, OptionalApiResponse helps make all fields optional, which can be useful when working with partially filled or optional data structures from an API.

## 4. Common Mistakes and Best Practices

### Common Mistakes

1.  Overusing Conditional Types: Overly complex conditional types can become hard to read and maintain. It’s best to use conditional types when necessary and keep them simple.
2.  Improper Use of Mapped Types: Forgetting to constrain keys in mapped types can lead to errors. For example, without keyof T, you might accidentally include extraneous keys.
3.  Misinterpreting Readonly Types: Making all properties readonly doesn’t guarantee immutability of nested objects. Deep immutability requires a recursive approach.

### Best Practices

- Use Constraints with Conditional Types: To avoid unexpected behaviors, use extends with conditional types to narrow down possible type outcomes.

```typescript
type OnlyStrings<T> = T extends string ? T : never;
```

- Leverage Utility Types: TypeScript has built-in utility types like Readonly, Partial, and Record that leverage mapped and conditional types. Using these built-in utilities where possible simplifies code and improves readability.
- Balance Flexibility and Complexity: While mapped and conditional types are powerful, avoid overcomplicating types for the sake of flexibility. Use them judiciously and prioritize code readability.
