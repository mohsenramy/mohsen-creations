### Source Control and Git with TypeScript

#### 1. Core Concept and Significance

**Source Control** is the practice of tracking and managing changes to code, which ensures that teams can collaborate efficiently and code changes are recorded, retrievable, and reversible. **Git** is one of the most popular distributed version control systems. It allows developers to save their work incrementally and work on different features in isolation (branches) without affecting the main codebase. Understanding Git is crucial for effective software development, particularly in teams.

In the context of **TypeScript**, the language doesn’t require any specific tools for Git integration. However, Git enables seamless collaboration, versioning, and code reviews, all of which are critical in a TypeScript project.

---

#### 2. Code Examples

Here are some basic Git commands and how you can manage a TypeScript project using Git:

1. **Commit Example:**

```bash
git init  # Initialize a new git repository
git add .  # Stage changes
git commit -m "Initial commit of TypeScript project"  # Commit changes
```

2. **Branch Example:**

```bash
git branch feature/new-api  # Create a new branch
git checkout feature/new-api  # Switch to the new branch
```

3. **Merge Example:**

```bash
git checkout main  # Switch back to the main branch
git merge feature/new-api  # Merge the feature branch into main
```

4. **Rebase Example:**

```bash
git checkout feature/new-api  # Switch to your branch
git rebase main  # Rebase your branch onto the latest main branch
```

### TypeScript and Git Integration

While TypeScript doesn't provide built-in Git support, **Git hooks** can be used to integrate linting, type checks, and formatting as part of the development process. Git hooks are custom scripts that run during specific Git events (e.g., pre-commit, pre-push). Tools like `Husky` can automate these hooks in TypeScript projects.

Example: A Git pre-commit hook that runs TypeScript checks using `Husky`.

```json
{
  "husky": {
    "hooks": {
      "pre-commit": "tsc --noEmit"
    }
  }
}
```

This ensures that no TypeScript errors are introduced during a commit.

### JSDoc Example

Below is an example of a TypeScript function with Git commands, properly documented using JSDoc:

```typescript
/**
 * Merges two branches in a Git repository.
 *
 * @param {string} sourceBranch - The branch you want to merge into the target.
 * @param {string} targetBranch - The branch to merge the source into.
 * @returns {string} - Returns a success message if merge is completed.
 * @throws {Error} - Throws an error if there is a merge conflict.
 */
function mergeBranches(sourceBranch: string, targetBranch: string): string {
  const execSync = require('child_process').execSync;

  try {
    execSync(`git checkout ${targetBranch}`);
    execSync(`git merge ${sourceBranch}`);
    return `Successfully merged ${sourceBranch} into ${targetBranch}`;
  } catch (error) {
    throw new Error('Merge conflict occurred!');
  }
}

console.log(mergeBranches('feature/new-api', 'main'));
```

### Explanation:

- `execSync` is a Node.js function that executes shell commands synchronously.
- The function attempts to merge a source branch into a target branch and throws an error if there’s a merge conflict.
- The **JSDoc comments** explain what each parameter does, what the function returns, and under what conditions it throws an error.

### 3. Practical Use Case

A common scenario for using Git in a TypeScript project is when multiple developers work on separate features or bug fixes. Each developer can:

1. Create a **branch** for their task, allowing isolation.
2. Regularly **commit** their work, ensuring progress is saved and traceable.
3. Merge or **rebase** with the main branch to incorporate the latest changes.

### Example Workflow:

- A developer working on a **TypeScript API feature** will branch out (`feature/api`), implement the changes, and make several commits.
- Once done, they will create a **pull request** (PR) and go through a **code review** process.
- After approval, the changes will be **merged** into the main branch.

This workflow ensures that:

- No one accidentally overwrites someone else's code.
- A clean history of changes is maintained.

### 4. Common Mistakes and Best Practices

#### Common Mistakes:

- **Committing compiled files**: In TypeScript, avoid committing compiled `.js` files. Use `.gitignore` to exclude `dist` or `build` folders.
- **Large commits**: Avoid making large, single commits. Instead, commit frequently with descriptive messages.
- **Not pulling latest changes before a push**: Always pull the latest changes from the main branch to avoid conflicts and rebase your branch if needed.

#### Best Practices:

1. **Branching Strategies**:

   - **Git Flow**: A robust branching strategy for handling large projects with multiple release cycles.
   - **GitHub Flow**: A simpler model where branches are created for features and merged into the main branch.
   - **Trunk-Based Development**: A practice of having a single branch (trunk) where all developers commit changes frequently.

2. **Code Review**: Always perform **code reviews** to catch bugs, enforce code quality, and ensure good practices.

3. **Rebasing**: Use **rebase** instead of merge to keep a cleaner Git history. Merging results in additional merge commits, while rebasing applies commits directly on top of the target branch.

4. **Cherry-pick**: Use `git cherry-pick <commit>` to selectively apply commits from one branch to another. This is useful when you need a specific feature or fix from another branch without merging the entire branch.

### Mastering Advanced Git Topics

- **Rebasing**: Instead of merging changes from the main branch, you can rebase, which applies your commits on top of the current branch, resulting in a linear history.

  Example:

  ```bash
  git checkout feature/my-feature
  git rebase main
  ```

- **Conflict Resolution**: When Git cannot automatically resolve conflicts during a merge or rebase, you'll need to manually edit conflicting files and mark them as resolved.

  Example of conflict markers in code:

  ```typescript
  <<<<<<< HEAD
  const apiVersion = "1.0";
  =======
  const apiVersion = "2.0";
  >>>>>>> feature/new-api
  ```

- **Cherry-picking**: Allows you to take specific commits from one branch and apply them to another.

  Example:

  ```bash
  git checkout main
  git cherry-pick abc1234  # Commit hash of the commit you want to pick
  ```
