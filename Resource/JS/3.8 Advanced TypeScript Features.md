### Advanced TypeScript Features

Advanced TypeScript features enable developers to write more expressive, flexible, and type-safe code. They make TypeScript an incredibly powerful tool for large-scale applications. In this guide, we'll explore **decorators**, **generics**, **type guards**, and **utility types**, demonstrating their significance, usage, and best practices.

---

## 1. **Decorators**

### Summary

**Decorators** in TypeScript are special functions that can modify classes, methods, accessors, properties, or parameters at design time. They are used to add metadata or alter the behavior of the decorated element. Decorators are commonly used in frameworks like Angular for dependency injection and service registration.

Decorators are currently a stage-2 proposal in ECMAScript and need the `"experimentalDecorators"` flag enabled in your `tsconfig.json`.

### Example: Class Decorator

```typescript
// Enable experimentalDecorators in tsconfig.json
// @Component is a decorator function
function Component(constructor: Function) {
  console.log(`Component registered: ${constructor.name}`);
}

// Apply the decorator to a class
@Component
class MyComponent {
  constructor() {
    console.log('MyComponent instantiated');
  }
}

const component = new MyComponent(); // Logs: "Component registered: MyComponent" and "MyComponent instantiated"
```

### Use Case

Decorators are useful in scenarios like:

- **Dependency Injection**: Managing object creation and lifecycle (Angular).
- **Logging and Analytics**: Wrapping methods to log execution or report data.

### Best Practices

- **Keep decorators simple**: Since decorators modify runtime behavior, they can make code harder to trace, so it's best to avoid complex logic in decorators.

## 2. **Generics**

### Summary

Generics allow you to create reusable components (functions, classes, interfaces) that work with different types while maintaining type safety. They provide flexibility while enforcing consistent data types throughout your code.

### Example: Generic Function

```typescript
/**
 * Identity function that returns whatever is passed in, while maintaining type safety.
 * @template T - Generic type placeholder
 * @param {T} arg - The input argument of any type
 * @returns {T} - Returns the same type as input
 */
function identity<T>(arg: T): T {
  return arg;
}

const resultNumber = identity<number>(5); // Explicitly passing the type
const resultString = identity('Hello'); // TypeScript infers the type (string)
```

### Built-In Support for Generics

- **Type Inference**: TypeScript can often infer the type when calling a generic function without explicitly specifying it.

### Use Case

Generics are vital in:

- **Data Structures**: Creating generic data structures like linked lists, stacks, and queues.
- **Reusable Utilities**: Functions like `map`, `filter`, and `reduce` that work with any type.

### Best Practices

- **Limit overly complex generic hierarchies**: Too many generics can make the code difficult to read and understand.

## 3. **Type Guards**

### Summary

**Type guards** allow you to narrow down types at runtime using conditionals. They ensure that code is type-safe by checking the actual type of an object before performing operations on it.

### Example: Using `typeof` and `instanceof`

```typescript
/**
 * Function that safely handles either a string or number input.
 * @param {string | number} input - Input can be either a string or number.
 * @returns {string} - Formatted string depending on the type of the input.
 */
function formatInput(input: string | number): string {
  if (typeof input === 'string') {
    return `String input: ${input}`;
  } else if (typeof input === 'number') {
    return `Number input: ${input}`;
  }
  throw new Error('Unsupported type');
}

console.log(formatInput('Hello')); // Output: "String input: Hello"
console.log(formatInput(42)); // Output: "Number input: 42"
```

### Built-In Support for Type Guards

- **`typeof` operator**: Used for primitive types like `string`, `number`, `boolean`.
- **`instanceof` operator**: Used for class-based objects.
- **Custom Type Guards**: You can create your own type guard functions using the `x is Y` syntax.

```typescript
function isString(input: any): input is string {
  return typeof input === 'string';
}
```

### Use Case

Type guards are especially useful in:

- **Handling union types**: Safely narrowing down types for function parameters that can take multiple types.

### Best Practices

- **Write custom type guards** for complex types that TypeScript can’t infer automatically.

## 4. **Utility Types**

### Summary

**Utility types** in TypeScript are built-in types that simplify common type transformations. These types enable more robust type definitions, particularly when working with object shapes.

### Key Utility Types:

- **Partial<T>**: Marks all properties of `T` as optional.

  ```typescript
  interface User {
    name: string;
    age: number;
  }

  const updateUser = (user: Partial<User>) => {
    // user can have any or none of the properties of User
  };
  ```

- **Pick<T, K>**: Constructs a new type by picking a subset of properties from `T`.

  ```typescript
  interface User {
    name: string;
    age: number;
    email: string;
  }

  type UserContactInfo = Pick<User, 'email' | 'name'>;
  ```

- **Record<K, T>**: Constructs an object type where keys are of type `K` and values are of type `T`.

  ```typescript
  const roleMap: Record<string, number> = {
    admin: 1,
    user: 2,
  };
  ```

### Use Case

Utility types are useful for:

- **Creating flexible APIs**: Handling optional fields, transforming object types.
- **Data Transformation**: Mapping between different types while ensuring type safety.

### Best Practices

- **Use Partial sparingly**: Overuse of `Partial` can make the code less strict and potentially introduce runtime issues due to missing properties.

## Conclusion

### Best Practices for Advanced TypeScript Features:

- **Decorators**: Use with caution to avoid complicating runtime behavior.
- **Generics**: Keep generic structures simple for readability and maintainability.
- **Type Guards**: Use to handle complex types safely at runtime.
- **Utility Types**: Leverage built-in utility types for common transformations, but ensure type clarity isn’t compromised.
