# Searching Algorithms in TypeScript

## 1. Core Concept and Significance

Searching algorithms are essential techniques in computer science for finding specific elements within a data structure. Depending on the structure and ordering of data, different search algorithms may offer various advantages in terms of speed and efficiency. TypeScript, while not offering built-in support for complex search algorithms, allows you to implement them using its type-safe features.

### Key Algorithms Covered:

1. **Linear Search**: Iteratively searches through each element in a list.
2. **Binary Search**: Searches efficiently by dividing a sorted array in half.
3. **Depth-First Search (DFS)**: Explores a graph by going as deep as possible before backtracking.
4. **Breadth-First Search (BFS)**: Explores a graph layer by layer, visiting all neighbors before going deeper.

## 2. Code Examples

### Linear Search

Linear search sequentially checks each element until it finds the target.

```typescript
/**
 * Performs a linear search on an array.
 * @param arr - The array to search within.
 * @param target - The element to find.
 * @returns The index of the target element or -1 if not found.
 */
function linearSearch<T>(arr: T[], target: T): number {
  for (let i = 0; i < arr.length; i++) {
    if (arr[i] === target) {
      return i;
    }
  }
  return -1;
}

const array = [10, 23, 3, 15];
console.log(linearSearch(array, 15)); // Output: 3
```

### Binary Search

Binary search is a faster algorithm that requires a sorted array, allowing it to halve the search space with each iteration.

```typescript
/**
 * Performs a binary search on a sorted array.
 * @param arr - The sorted array to search within.
 * @param target - The element to find.
 * @returns The index of the target element or -1 if not found.
 */
function binarySearch(arr: number[], target: number): number {
  let left = 0;
  let right = arr.length - 1;

  while (left <= right) {
    const mid = Math.floor((left + right) / 2);
    if (arr[mid] === target) {
      return mid;
    } else if (arr[mid] < target) {
      left = mid + 1;
    } else {
      right = mid - 1;
    }
  }
  return -1;
}

const sortedArray = [3, 10, 15, 23, 42];
console.log(binarySearch(sortedArray, 15)); // Output: 2
```

### Depth-First Search (DFS)

DFS explores a graph by going as deep as possible along each branch before backtracking.

```typescript
/**
 * Performs a Depth-First Search (DFS) traversal on a graph represented with objects.
 * @param graph - An object representing the graph as an adjacency list.
 * @param start - The starting node for the traversal.
 * @returns An array of nodes in the order they were visited.
 */
function depthFirstSearch(
  graph: { [key: string]: string[] },
  start: string
): string[] {
  const visited = new Set<string>();
  const result: string[] = [];

  function dfs(node: string) {
    if (visited.has(node)) return;
    visited.add(node);
    result.push(node);

    const neighbors = graph[node] || [];
    for (const neighbor of neighbors) {
      dfs(neighbor);
    }
  }

  dfs(start);
  return result;
}

// Example Graph
const graphDFS = {
  A: ['B', 'C'],
  B: ['A', 'D', 'E'],
  C: ['A', 'F'],
  D: ['B'],
  E: ['B', 'F'],
  F: ['C', 'E'],
};

console.log(depthFirstSearch(graphDFS, 'A')); // Output: ["A", "B", "D", "E", "F", "C"]
```

### Breadth-First Search (BFS)

BFS explores each layer of a graph, visiting all neighboring nodes before moving deeper.

```typescript
/**
 * Performs a Breadth-First Search (BFS) traversal on a graph represented with objects.
 * @param graph - An object representing the graph as an adjacency list.
 * @param start - The starting node for the traversal.
 * @returns An array of nodes in the order they were visited.
 */
function breadthFirstSearch(
  graph: { [key: string]: string[] },
  start: string
): string[] {
  const visited = new Set<string>();
  const result: string[] = [];
  const queue: string[] = [start];

  while (queue.length > 0) {
    const node = queue.shift()!;
    if (visited.has(node)) continue;

    visited.add(node);
    result.push(node);

    const neighbors = graph[node] || [];
    for (const neighbor of neighbors) {
      if (!visited.has(neighbor)) {
        queue.push(neighbor);
      }
    }
  }
  return result;
}

// Example Graph
const graphBFS = {
  A: ['B', 'C'],
  B: ['A', 'D', 'E'],
  C: ['A', 'F'],
  D: ['B'],
  E: ['B', 'F'],
  F: ['C', 'E'],
};

console.log(breadthFirstSearch(graphBFS, 'A')); // Output: ["A", "B", "C", "D", "E", "F"]
```

### Why These Functions Aren't Searching for a Specific Value

The above implementations of DFS and BFS are designed for **traversing** the graph, meaning they will visit each node and explore its neighbors. This is useful for:

- **Exploring all nodes**: Checking the entire structure, like finding all connected nodes in a network.
- **Pathfinding**: Identifying a path from the start node to the destination node.

#### How to Modify for Searching

To actually search for a specific value in DFS or BFS, you’d include a condition within each traversal to check if the current node matches the target value. If the value is found, you can return the path, node, or simply stop the traversal. Here's a quick example of searching with BFS:

```typescript
/**
 * Searches for a target value in a graph using BFS.
 * @param graph - An object representing the graph as an adjacency list.
 * @param start - The starting node for the search.
 * @param target - The node value to search for.
 * @returns The path to the target node if found, or null if not found.
 */
function bfsSearch(
  graph: { [key: string]: string[] },
  start: string,
  target: string
): string[] | null {
  const visited = new Set<string>();
  const queue: string[] = [start];
  const path: string[] = [];

  while (queue.length > 0) {
    const node = queue.shift()!;
    if (visited.has(node)) continue;

    visited.add(node);
    path.push(node);

    if (node === target) return path; // Found the target, return the path

    const neighbors = graph[node] || [];
    for (const neighbor of neighbors) {
      if (!visited.has(neighbor)) {
        queue.push(neighbor);
      }
    }
  }

  return null; // Target not found
}

console.log(bfsSearch(graphBFS, 'A', 'F')); // Output: ["A", "B", "E", "F"]
```

#### Key Points

1. **Traversal vs. Search**: Traversal means exploring the entire graph or tree, while search aims to locate a specific value.
2. **Stopping Early**: In search mode, the algorithm can stop early when the target value is found, improving efficiency.
3. **DFS and BFS Use-Cases**:
   - **DFS**: Good for scenarios where exploring as deep as possible first is important, like solving mazes.
   - **BFS**: Suitable for finding the shortest path in unweighted graphs because it explores layer by layer.

## 3. Practical Use Cases

- **Linear Search**: Suitable for small datasets or unsorted arrays where simplicity is more important than speed.
- **Binary Search**: Ideal for large, sorted datasets where quick lookups are essential, such as database indexes or sorted arrays.
- **DFS**: Useful in scenarios requiring exhaustive searches like puzzle solvers, maze traversals, or pathfinding algorithms.
- **BFS**: Commonly used for finding the shortest path in unweighted graphs, as seen in social network analysis or routing algorithms.

## 4. Common Mistakes and Best Practices

### Mistakes

- **Using Binary Search on Unsorted Data**: Binary Search requires sorted data; using it on unsorted data will result in incorrect results.
- **Infinite Loops in DFS/BFS**: Not marking visited nodes can lead to infinite loops in cyclic graphs.
- **Stack Overflow in DFS**: In very deep trees, DFS can lead to stack overflow errors due to recursive calls.

### Best Practices

- **Choose the Right Algorithm**: Use the algorithm that best matches the problem context to ensure efficiency.
- **Validate Inputs**: For Binary Search, ensure the array is sorted. For graph searches, validate node connections.
- **Optimize for Graph Size**: Use BFS for shallow searches or finding shortest paths; use DFS for exhaustive searches.
