# Node.js Streams in TypeScript

## 1. Core Concept and Significance

**Node.js Streams** provide a way to handle data that’s either too large to be processed at once or needs to be processed incrementally. A stream is essentially a continuous flow of data, enabling you to read or write data piece-by-piece rather than loading it all at once. This makes streams highly memory-efficient and ideal for handling large data sets, such as files or data from network sources.

### Why Streams Are Important:

- **Memory Efficiency**: Streams process data in chunks, reducing memory consumption.
- **Time Efficiency**: They allow you to start processing data as soon as it arrives, without waiting for the entire data set.
- **I/O Optimization**: Streams are optimized for handling I/O-bound tasks, especially with large data sets.

## 2. Types of Streams and Use Cases

### 1. **Readable Streams**

- Used to read data from a source.
- Examples: File reading, HTTP requests.

### 2. **Writable Streams**

- Used to write data to a destination.
- Examples: Writing to a file, sending data over HTTP.

### 3. **Duplex Streams**

- Implement both readable and writable interfaces, allowing bidirectional communication.
- Examples: Sockets, network communication.

### 4. **Transform Streams**

- A type of duplex stream that can modify or transform the data as it is read or written.
- Examples: Compressing, encrypting data.

## 3. Code Examples

Here's how each stream type can be implemented in TypeScript:

### Example 1: Using Readable and Writable Streams

```typescript
import * as fs from 'fs';
import { Readable, Writable } from 'stream';

/**
 * Logs content from a readable stream.
 * @param {Readable} readableStream - The readable stream source.
 */
function logStreamContent(readableStream: Readable): void {
  readableStream.on('data', (chunk) => {
    console.log(`Received chunk: ${chunk}`);
  });
  readableStream.on('end', () => {
    console.log('No more data in stream.');
  });
}

/**
 * Writes content to a writable stream.
 * @param {Writable} writableStream - The writable stream destination.
 * @param {string} data - The data to write.
 */
function writeToStream(writableStream: Writable, data: string): void {
  writableStream.write(data, 'utf-8', () => {
    console.log('Data written to stream.');
  });
  writableStream.end(() => {
    console.log('Finished writing data.');
  });
}

// Usage
const readableStream = fs.createReadStream('path/to/input/file.txt');
const writableStream = fs.createWriteStream('path/to/output/file.txt');

logStreamContent(readableStream);
writeToStream(writableStream, 'Hello, Node.js Streams!');
```

### Example 2: Using Transform Streams

```typescript
import { Transform } from 'stream';

/**
 * Creates a transform stream that converts data to uppercase.
 * @returns {Transform} Transform stream.
 */
function createUppercaseTransformStream(): Transform {
  return new Transform({
    transform(chunk, encoding, callback) {
      this.push(chunk.toString().toUpperCase());
      callback();
    },
  });
}

// Usage
const transformStream = createUppercaseTransformStream();
process.stdin.pipe(transformStream).pipe(process.stdout);
```

This example reads from the standard input, transforms the data to uppercase, and outputs it to the standard output. It's a simple example, but transform streams are powerful for tasks like data compression, encryption, and format conversion.

## 4. TypeScript Support

TypeScript provides built-in types for Node.js streams via the `stream` module, so you can use types like `Readable`, `Writable`, `Duplex`, and `Transform` directly. This support ensures type safety and helps catch errors during compile time.

## 5. Practical Use Case

Streams are particularly useful when:

- **Handling Large Files**: Instead of loading an entire file into memory, you can process it in chunks.
- **Real-Time Data Processing**: Applications like video streaming, audio processing, or live data feeds where data flows continuously.

For example, if you're processing large log files, you can use streams to read each line and analyze or transform it on-the-fly without using a lot of memory.

## 6. Common Mistakes and Best Practices

### Common Mistakes:

1. **Forgetting to Handle Errors**: Always include error handling (`on('error')`) to avoid unhandled exceptions.
2. **Incorrect Stream Piping**: Ensure compatible streams are piped correctly (e.g., don't pipe a readable stream into another readable stream).
3. **Memory Leaks**: Avoid storing large amounts of data in buffers within streams, as this negates the memory efficiency advantage.

### Best Practices:

- **Use `pipe()` for Stream Chaining**: It’s built-in and handles errors properly.
- **Limit Concurrency**: For large data operations, limit the number of concurrent streams to avoid overloading the system.
- **Backpressure Handling**: Use the `drain` and `pause`/`resume` methods to manage backpressure in writable streams.
