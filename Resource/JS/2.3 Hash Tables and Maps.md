# Hash Tables & Maps in TypeScript

## 1. Core Concept and Significance

Hash Tables are data structures that store data as key-value pairs. Maps are a built-in TypeScript/JavaScript data structure implementing hash tables, which allow for efficient data retrieval and handling of any data type as keys.

### Importance:

- Efficiency: Constant-time complexity for most operations.
- Flexible Keys: Unlike plain objects, Map allows any type of key (not just strings).
- Maintains Order: In Map, keys are iterated in the order of insertion.

## 2. Code Examples with Detailed Comments

### Example 3: Custom Hash Table with Collision Resolution (Chaining)

```typescript
// Creating a HashTable class that handles collisions using chaining
class HashTable<K, V> {
  private buckets: Array<[K, V][]>;

  // Initialize hash table with a fixed size
  constructor(private size: number = 10) {
    this.buckets = Array(size)
      .fill(null)
      .map(() => []);
  }

  // Hash function to determine the bucket index for a key
  private hash(key: K): number {
    // Convert the key to a string, then get the length modulo size
    return String(key).length % this.size;
  }

  // Set a value in the hash table
  set(key: K, value: V): void {
    const index = this.hash(key);
    const bucket = this.buckets[index];

    // Check if the key exists in the bucket; update if found
    for (const entry of bucket) {
      if (entry[0] === key) {
        entry[1] = value;
        return;
      }
    }

    // Key not found; add a new entry
    bucket.push([key, value]);
  }

  // Get a value by key from the hash table
  get(key: K): V | undefined {
    const index = this.hash(key);
    const bucket = this.buckets[index];

    // Find the key in the bucket and return its value
    for (const [k, v] of bucket) {
      if (k === key) return v;
    }
    return undefined; // Key not found
  }
}

const table = new HashTable<string, string>();
table.set('apple', 'fruit');
table.set('carrot', 'vegetable');

console.log(table.get('apple')); // Output: fruit
```

Here, the custom HashTable class uses chaining for collision resolution. Each bucket holds an array of key-value pairs. If multiple keys hash to the same bucket, they are stored in a list, thus preventing overwrites.

## 3. Practical Use Case

### Use Case: Caching Data for Quick Access

Suppose you need to cache user data for rapid access. A hash table allows you to map user IDs (or other unique identifiers) to user information.

Map is ideal here, as it enables quick lookups, and user data retrieval is instantaneous.

## 4. Common Mistakes and Best Practices

### Common Mistakes

1. **Using Objects for Non-String Keys**: Objects can only have string or symbol keys. Use Map for more flexible key types.
2. **Ignoring Collision Handling**: In custom hash tables, ignoring collisions can cause data overwrites.

### Best Practices

- **Prefer Map for Non-String Keys**: Map allows for a wide variety of key types and maintains insertion order.
- **Design Efficient Hash Functions**: Ensure your hash function uniformly distributes keys across buckets to reduce clustering.
- **Consider WeakMap for Short-Lived Keys**: WeakMap automatically removes entries when keys are no longer used, useful for memory-sensitive cases.

### 1. Core Concept and Significance

**Hash Tables** and **Maps** are data structures used to store key-value pairs and allow for fast data retrieval. A key is mapped to a value using a hashing function that computes an index for storing data. In **TypeScript**, these structures are essential for efficient lookups, data organization, and ensuring scalability in performance-critical applications.

### 2. Code Examples

#### Example 1: Implementing a Simple Hash Table in TypeScript

```typescript
/**
 * A basic implementation of a hash table using chaining for collision resolution.
 */
class HashTable<K, V> {
  private table: Array<Array<[K, V]>>;
  private size: number;

  constructor(size: number = 50) {
    this.table = new Array(size);
    this.size = size;
  }

  /**
   * Hashing function to calculate the index from the key.
   * @param key - The key to hash.
   * @returns A number representing the index for the key.
   */
  private hash(key: K): number {
    let hash = 0;
    const strKey = String(key);
    for (let i = 0; i < strKey.length; i++) {
      hash += strKey.charCodeAt(i);
    }
    return hash % this.size;
  }

  /**
   * Adds a key-value pair to the hash table.
   * Uses chaining to handle collisions.
   * @param key - The key to be added.
   * @param value - The value associated with the key.
   */
  public set(key: K, value: V): void {
    const index = this.hash(key);
    if (!this.table[index]) {
      this.table[index] = [];
    }
    // Handle collisions via chaining (linked list)
    for (const pair of this.table[index]) {
      if (pair[0] === key) {
        pair[1] = value; // Update if key exists
        return;
      }
    }
    this.table[index].push([key, value]);
  }

  /**
   * Retrieves the value for a given key.
   * @param key - The key to look up.
   * @returns The value associated with the key, or undefined if not found.
   */
  public get(key: K): V | undefined {
    const index = this.hash(key);
    const bucket = this.table[index];
    if (bucket) {
      for (const pair of bucket) {
        if (pair[0] === key) {
          return pair[1];
        }
      }
    }
    return undefined;
  }

  /**
   * Removes a key-value pair from the hash table.
   * @param key - The key to remove.
   * @returns True if the key was found and removed, false otherwise.
   */
  public remove(key: K): boolean {
    const index = this.hash(key);
    const bucket = this.table[index];
    if (bucket) {
      for (let i = 0; i < bucket.length; i++) {
        if (bucket[i][0] === key) {
          bucket.splice(i, 1);
          return true;
        }
      }
    }
    return false;
  }
}

// Example usage:
const myHashTable = new HashTable<string, number>(100);
myHashTable.set('apple', 5);
myHashTable.set('banana', 8);
console.log(myHashTable.get('apple')); // 5
console.log(myHashTable.get('banana')); // 8
```

#### Explanation:

- **Hashing:** Converts a key into an array index using a simple algorithm (sum of character codes modulo table size).
- **Chaining:** Handles collisions by storing multiple key-value pairs at the same index using an array of arrays.
- **JSDoc comments** help in understanding what each method does and its parameters and return values.

### 4. Practical Use Case

A common scenario for hash tables and maps is **caching**, where quick lookups of previously computed or fetched data are necessary.

Example: Implementing an LRU Cache (Least Recently Used) with a Map.

```typescript
/**
 * Implements a simple LRU Cache using a Map.
 */
class LRUCache<K, V> {
  private capacity: number;
  private cache: Map<K, V>;

  constructor(capacity: number) {
    this.capacity = capacity;
    this.cache = new Map();
  }

  /**
   * Adds a key-value pair to the cache.
   * @param key - The key for the cache.
   * @param value - The value to store.
   */
  public set(key: K, value: V): void {
    if (this.cache.has(key)) {
      this.cache.delete(key); // Remove and re-add to update access order
    } else if (this.cache.size >= this.capacity) {
      // Remove the oldest accessed item
      const firstKey = this.cache.keys().next().value;
      this.cache.delete(firstKey);
    }
    this.cache.set(key, value);
  }

  /**
   * Retrieves the value for a given key.
   * @param key - The key to retrieve from the cache.
   * @returns The value associated with the key, or undefined if not found.
   */
  public get(key: K): V | undefined {
    if (!this.cache.has(key)) return undefined;
    const value = this.cache.get(key);
    this.cache.delete(key); // Move to most recently used
    this.cache.set(key, value!);
    return value;
  }
}

// Example usage
const lruCache = new LRUCache<string, number>(3);
lruCache.set('a', 1);
lruCache.set('b', 2);
lruCache.set('c', 3);
lruCache.get('a'); // Access to refresh order
lruCache.set('d', 4); // Removes "b" (least recently used)
```

#### Explanation:

- This LRU cache is implemented using a `Map`, which efficiently maintains the order of key accesses.
- When a key is accessed, it is refreshed to be the most recently used, and the least used key is evicted once capacity is reached.

### 5. Common Mistakes and Best Practices

- **Collision Resolution:** Always choose a robust collision resolution strategy like chaining or open addressing.
- **Key Types:** Prefer `Map` when you need to use non-string keys or when insertion order matters. Using `Object` forces string coercion for all keys.
- **Performance:** Maps have slightly better performance for frequent key lookups compared to plain objects.
- **Garbage Collection:** For memory-heavy operations involving objects as keys, `WeakMap` can help by allowing garbage collection of unreferenced keys.

### 6. Hashing Concepts & Collision Resolution

- **Hashing:** A process where a key is transformed into a unique array index. A good hash function distributes keys uniformly to minimize collisions.
- **Collisions:** Occur when multiple keys hash to the same index.
  - **Chaining:** Uses linked lists or arrays at each bucket to store multiple key-value pairs.
  - **Open Addressing:** Probes for the next available spot in the array to resolve collisions.

### 7. Maps vs. Objects

- **Objects:** Keys are coerced into strings or symbols, and insertion order is not guaranteed for all operations.
- **Maps:** Maintain key type integrity, allow any value as a key, and guarantee insertion order.
