**Type narrowing** in TypeScript refers to the process of refining the type of a variable within a specific block of code. Since TypeScript often deals with **union types** (variables that can be of multiple possible types), narrowing helps in determining the **specific type** of a variable at runtime, allowing TypeScript to provide better type safety and enable access to methods and properties relevant to that type.

### Core Concept and Significance

When you use **type guards** (like `typeof`, `instanceof`, or `in`), TypeScript automatically narrows the type of the variable within a certain scope (e.g., an `if` block). This gives you confidence that within that block, the variable can be treated as having a specific type, improving both the safety and expressiveness of your code.

### Examples of Type Narrowing in TypeScript

Here are several common ways to narrow types in TypeScript:

#### 1. **Using `typeof` for Primitives**

`typeof` is commonly used to narrow types when you're dealing with **primitive types** such as `string`, `number`, `boolean`, etc.

```typescript
type ID = string | number;

/**
 * Function that prints an ID, handling both strings and numbers.
 * @param {ID} id - The ID, which can be a string or a number.
 */
function printId(id: ID) {
  if (typeof id === 'string') {
    // Narrowed to string, so now we can use string-specific methods
    console.log(id.toUpperCase());
  } else {
    // Narrowed to number, so now we can use number-specific methods
    console.log(id.toFixed(2));
  }
}

printId('abc'); // ABC
printId(123.456); // 123.46
```

#### Explanation

In this example, `typeof id === "string"` is a **type guard** that narrows the type of `id` to `string` within the `if` block, allowing you to use string-specific methods. In the `else` block, `id` is treated as a `number`.

---

#### 2. **Using `instanceof` for Objects**

`instanceof` is used for narrowing when you're dealing with **class instances** or objects.

```typescript
class Dog {
  bark() {
    return 'Woof!';
  }
}

class Cat {
  meow() {
    return 'Meow!';
  }
}

type Pet = Dog | Cat;

/**
 * Function to describe a pet based on its type (Dog or Cat)
 * @param {Pet} pet - The pet, which can be either a Dog or Cat.
 */
function makeSound(pet: Pet) {
  if (pet instanceof Dog) {
    // Narrowed to Dog, can call Dog-specific methods
    console.log(pet.bark());
  } else {
    // Narrowed to Cat, can call Cat-specific methods
    console.log(pet.meow());
  }
}

makeSound(new Dog()); // Woof!
makeSound(new Cat()); // Meow!
```

#### Explanation

In this example, `pet instanceof Dog` narrows the type to `Dog` within the `if` block, so you can safely call the `bark()` method. In the `else` block, the type is narrowed to `Cat`, and you can call `meow()`.

---

#### 3. **Using `in` for Object Properties**

`in` is useful for narrowing when dealing with **objects that share some properties but differ in others**.

```typescript
type Car = {
  make: string;
  fuelType: 'gasoline' | 'electric';
};

type Bicycle = {
  make: string;
  hasPedals: boolean;
};

type Vehicle = Car | Bicycle;

/**
 * Function that describes a vehicle based on its properties
 * @param {Vehicle} vehicle - The vehicle, which can be a Car or Bicycle.
 */
function describeVehicle(vehicle: Vehicle) {
  console.log(`Make: ${vehicle.make}`);

  if ('fuelType' in vehicle) {
    // Narrowed to Car, can access Car-specific properties
    console.log(`Fuel Type: ${vehicle.fuelType}`);
  } else {
    // Narrowed to Bicycle, can access Bicycle-specific properties
    console.log(`Has Pedals: ${vehicle.hasPedals}`);
  }
}

const myCar: Car = { make: 'Tesla', fuelType: 'electric' };
const myBike: Bicycle = { make: 'Giant', hasPedals: true };

describeVehicle(myCar); // Make: Tesla, Fuel Type: electric
describeVehicle(myBike); // Make: Giant, Has Pedals: true
```

#### Explanation

Here, the `in` operator checks if the `fuelType` property exists on the `vehicle`. If it does, TypeScript narrows the type to `Car`. Otherwise, it narrows the type to `Bicycle`.

#### 4. **Custom Type Guards**

You can create custom type guards by defining functions that return a boolean value and use them for narrowing.

```typescript
type Fish = { swim: () => void };
type Bird = { fly: () => void };

function isFish(pet: Fish | Bird): pet is Fish {
  return (pet as Fish).swim !== undefined;
}

/**
 * Function to describe the action of a pet (Fish or Bird)
 * @param {Fish | Bird} pet - The pet, which can be a Fish or Bird.
 */
function move(pet: Fish | Bird) {
  if (isFish(pet)) {
    // Narrowed to Fish
    pet.swim();
  } else {
    // Narrowed to Bird
    pet.fly();
  }
}

const myFish: Fish = { swim: () => console.log('Swimming!') };
const myBird: Bird = { fly: () => console.log('Flying!') };

move(myFish); // Swimming!
move(myBird); // Flying!
```

#### Explanation

In this example, the `isFish()` function is a **custom type guard**. It checks whether the `pet` has a `swim` method, and if so, narrows the type to `Fish`. Otherwise, the type is narrowed to `Bird`.

### Built-in TypeScript Support for Narrowing

TypeScript **automatically infers** type narrowing inside conditional blocks. This means that TypeScript will figure out the most specific type of a variable within `if`, `else`, and other conditionals based on the type guards you use (`typeof`, `instanceof`, etc.).

For example, after `typeof value === 'string'`, TypeScript knows that `value` is a `string` within that block, enabling access to all string-specific methods.

### Practical Use Case for Type Narrowing

**API Responses Handling**: When dealing with API responses, the return type could vary depending on the response status. Type narrowing can help handle different possible shapes of the response.

```typescript
type SuccessResponse = {
  status: 'success';
  data: string;
};

type ErrorResponse = {
  status: 'error';
  error: string;
};

type ApiResponse = SuccessResponse | ErrorResponse;

/**
 * Function to handle different types of API responses
 * @param {ApiResponse} response - The response from the API
 */
function handleApiResponse(response: ApiResponse) {
  if (response.status === 'success') {
    // Narrowed to SuccessResponse
    console.log(`Data: ${response.data}`);
  } else {
    // Narrowed to ErrorResponse
    console.log(`Error: ${response.error}`);
  }
}

const success: SuccessResponse = { status: 'success', data: 'User data' };
const error: ErrorResponse = { status: 'error', error: 'Failed to fetch data' };

handleApiResponse(success); // Data: User data
handleApiResponse(error); // Error: Failed to fetch data
```

#### Explanation:

Type narrowing helps handle different types of API responses by distinguishing between the `SuccessResponse` and `ErrorResponse` based on the `status` property.

### Common Mistakes and Best Practices

#### Common Mistakes:

1. **Missing Type Guard**: Not using proper type guards like `typeof`, `instanceof`, or custom guards may result in runtime errors.
2. **Overusing Type Assertions**: Using type assertions (e.g., `as Type`) instead of type guards can bypass TypeScript’s type checking and lead to unsafe code.
3. **Ignoring Edge Cases**: When narrowing, make sure all possible types are handled, especially when using union types.

#### Best Practices:

1. **Always Use Type Guards**: Use `typeof`, `instanceof`, and `in` to narrow types safely.
2. **Handle All Cases**: When working with union types, always ensure that you handle all possible types to avoid unexpected behaviors.
3. **Use Custom Type Guards for Complex Types**: When working with more complex objects, custom type guards can make your code clearer and more robust.

---

### Conclusion

Type narrowing is a core feature in TypeScript that enhances type safety by refining types within specific code blocks. By using type guards (`typeof`, `instanceof`, `in`), you can safely access properties and methods specific to a type, ensuring your code is both safe and expressive.
