# 1.2. Async Patterns in TypeScript

## Core Concept and Significance

Asynchronous programming is crucial in JavaScript and TypeScript to handle operations that take time to complete, such as fetching data from a server, file I/O, or executing timers, without blocking the rest of the code execution.

There are three common patterns for managing asynchronous behavior:

### Callbacks

A **callback** is a function passed into another function as an argument and is executed after some asynchronous task has completed.

### Promises

A **Promise** represents the eventual completion (or failure) of an asynchronous operation and its resulting value. Promises provide a cleaner alternative to callbacks by allowing chaining of operations through `.then()`.

### Async/Await

`async/await` is syntactic sugar built on top of Promises. It makes asynchronous code look and behave more like synchronous code, leading to more readable and maintainable code.

### Significance

Using async patterns allows applications to handle asynchronous tasks (like API requests, file handling, etc.) without freezing or blocking the main thread. This is vital for building responsive, performant applications.

## 2. Code Example

Here's an example of how the different async patterns work in TypeScript:

```typescript
// Callback example
function fetchDataCallback(url: string, callback: (data: string) => void) {
  setTimeout(() => {
    callback(`Data from ${url}`);
  }, 1000);
}

fetchDataCallback('https://api.example.com', (data) => {
  console.log('Callback received:', data);
});

// Promise example
function fetchDataPromise(url: string): Promise<string> {
  return new Promise((resolve) => {
    setTimeout(() => {
      resolve(`Data from ${url}`);
    }, 1000);
  });
}

fetchDataPromise('https://api.example.com').then((data) => {
  console.log('Promise received:', data);
});

// Async/Await example
async function fetchDataAsync(url: string): Promise<string> {
  const data = await fetchDataPromise(url);
  console.log('Async/Await received:', data);
}

fetchDataAsync('https://api.example.com');
```

### Key Parts of the Code:

- **Callback**: `fetchDataCallback` simulates a delayed API call and executes the provided callback after completion.
- **Promise**: `fetchDataPromise` returns a promise that resolves after a delay, demonstrating how to handle asynchronous tasks using promises.
- **Async/Await**: `fetchDataAsync` uses `await` to pause execution until the promise resolves, providing a cleaner syntax for handling async operations.

## 3. Practical Use Case

### Use Case: API Requests

In modern web development, handling API requests is a common async task. Using `async/await` in TypeScript allows developers to write clean and readable code when making multiple API requests.

```typescript
async function getUserData(userId: number): Promise<void> {
  try {
    const user = await fetch(`https://api.example.com/users/${userId}`).then(
      (res) => res.json()
    );
    console.log('User Data:', user);

    const posts = await fetch(
      `https://api.example.com/users/${userId}/posts`
    ).then((res) => res.json());
    console.log('User Posts:', posts);
  } catch (error) {
    console.error('Error fetching data:', error);
  }
}

getUserData(1);
```

This example shows how `async/await` helps avoid callback hell or chaining multiple `.then()` calls when handling multiple API requests. It makes the code easier to read and reason about.

## 4. Common Mistakes and Best Practices

### Common Mistakes:

1. **Not handling errors**: When using promises or `async/await`, always handle potential errors using `.catch()` for promises or `try/catch` for `async/await`.
2. **Blocking the main thread**: Be cautious when working with async code inside synchronous functions. Async tasks should never block the main thread.
3. **Overusing `await`**: Avoid using `await` inside loops if the iterations can be executed in parallel. Instead, use `Promise.all()` for concurrent execution.

```typescript
// Example of better parallel execution with Promise.all
async function fetchMultipleUrls(urls: string[]): Promise<void> {
  const promises = urls.map((url) => fetchDataPromise(url));
  const results = await Promise.all(promises);
  console.log(results);
}

fetchMultipleUrls(['https://api.example.com/1', 'https://api.example.com/2']);
```

### Best Practices:

- **Use `async/await` for readability**: Whenever possible, prefer `async/await` over promise chaining for better code readability.
- **Error handling**: Always include error handling for promises using `.catch()` or `try/catch` blocks for `async/await`.
- **Parallel execution**: When multiple asynchronous operations can be run concurrently, use `Promise.all()` to avoid unnecessary delays.
