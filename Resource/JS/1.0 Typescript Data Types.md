### 1. Core Concept: TypeScript DataTypes and Their Significance

TypeScript is a statically typed superset of JavaScript, which means you explicitly define variable types. This adds an extra layer of type safety, helping catch errors during development and making code more predictable and self-documented. The major benefit is improved maintainability and tooling support, as TypeScript helps avoid common mistakes that occur in loosely typed languages like JavaScript.

#### Key Concepts:

- **Static Typing**: Variables are given specific types (e.g., `string`, `number`) when defined.
- **Type Inference**: TypeScript can often infer types automatically based on the assigned values.
- **Special Types**: These include unions, literals, enums, and others that give you fine-grained control over types.

### 2. Code Examples with Explanations

#### Variables Definitions in TypeScript

You define variables with explicit types for clarity:

```typescript
/**
 * Adds two numbers together.
 * @param {number} a - The first number.
 * @param {number} b - The second number.
 * @returns {number} - The sum of `a` and `b`.
 */
function add(a: number, b: number): number {
  return a + b;
}

const result: number = add(5, 10); // result is a number
```

#### Var, Const, Let Comparison

- **`var`**: Function-scoped. Allows re-declaration and hoisting. Best avoided due to its scope issues.
- **`let`**: Block-scoped. Does not allow re-declaration within the same block, preventing bugs related to variable shadowing.
- **`const`**: Block-scoped. Like `let` but creates constants that cannot be re-assigned.

Example:

```typescript
function testVarLetConst(): void {
  if (true) {
    var x = 10; // function-scoped
    let y = 20; // block-scoped
    const z = 30; // block-scoped and constant
  }
  console.log(x); // Accessible because of var hoisting
  // console.log(y); // Error: y is not defined
  // console.log(z); // Error: z is not defined
}

testVarLetConst();
```

#### Hoisting & Scope

**Hoisting** is a JavaScript mechanism where variables and function declarations are moved to the top of their scope before execution. However, `let` and `const` variables are hoisted but not initialized until their definition.

Example:

```typescript
console.log(hoistedVar); // undefined (due to hoisting)
var hoistedVar = 5;

console.log(hoistedLet); // Error: Cannot access 'hoistedLet' before initialization
let hoistedLet = 10;
```

#### Data Types

1. **Primitive Types**

   - **Number**: `let age: number = 25;`
   - **String**: `let name: string = "John";`
   - **Boolean**: `let isActive: boolean = true;`
   - **Null**: `let empty: null = null;`
   - **Undefined**: `let notAssigned: undefined = undefined;`

2. **Arrays**

   - Defined with type and square brackets (`[]`).

   ```typescript
   let numbers: number[] = [1, 2, 3];
   let names: string[] = ['Alice', 'Bob'];
   ```

3. **Tuples**

   - Fixed-length arrays with defined types for each element.

   ```typescript
   let person: [string, number] = ['Alice', 30]; // A string and a number
   ```

4. **Union Types**

   - A variable can be of multiple types.

   ```typescript
   let result: string | number;
   result = 'Success'; // Ok
   result = 200; // Ok
   ```

5. **Literal Types**

   - Variables can only take specific literal values.

   ```typescript
   let direction: 'north' | 'south' | 'east' | 'west';
   direction = 'north'; // Ok
   // direction = "up"; // Error
   ```

6. **Enums**

   - A way to define named constants.

   ```typescript
   enum Color {
     Red = 1,
     Green,
     Blue,
   }

   let c: Color = Color.Green;
   console.log(c); // Outputs 2
   ```

7. **Type Aliases**

   - You can create custom types by aliasing existing ones.

   ```typescript
   type ID = number | string;
   let userId: ID = 123;
   userId = 'ABC123';
   ```

8. **Any**

   - Disables type checking for a variable. Avoid using it unless necessary.

   ```typescript
   let anything: any = 42;
   anything = 'A string now'; // Ok
   ```

9. **Void**

   - Represents the absence of a value (typically used with functions that don’t return a value).

   ```typescript
   function logMessage(message: string): void {
     console.log(message);
   }
   ```

10. **Never**

    - Represents values that never occur, often used in functions that always throw an error or have infinite loops.

    ```typescript
    function throwError(message: string): never {
      throw new Error(message);
    }
    ```

### 3. Practical Use Case

Suppose you're building an API where user input is either a string username or a numeric user ID. Using **union types** ensures you handle both cases:

```typescript
/**
 * Fetches user data by either ID or username.
 * @param {string | number} identifier - The user's ID or username.
 * @returns {string} - A message with the user's information.
 */
function getUserInfo(identifier: string | number): string {
  if (typeof identifier === 'string') {
    return `Fetching data for user: ${identifier}`;
  } else {
    return `Fetching data for user ID: ${identifier}`;
  }
}

console.log(getUserInfo('Alice'));
console.log(getUserInfo(12345));
```

### 4. Common Mistakes and Best Practices

- **Overusing `any`**: While `any` can be useful for quick prototyping, overusing it defeats the purpose of static typing. Always prefer more specific types.
- **Avoiding Type Annotations**: Relying solely on type inference can sometimes lead to unclear code. Explicit types improve code readability and maintenance.
- **`var` usage**: Avoid `var` in favor of `let` and `const` to prevent hoisting-related bugs.
- **Enums and Number Values**: Be cautious with number-based enums, as their values increment automatically unless explicitly set.
