# 1.4. Immutability & Pure Functions in TypeScript

## Core Concept and Significance

Immutability refers to the concept where an object cannot be modified after it is created. Instead of changing the existing object, any updates create a new object. This concept is crucial in functional programming and helps to avoid side effects, making code easier to understand and maintain.

Pure Functions are functions that, given the same inputs, will always produce the same outputs without causing any side effects. A pure function does not alter any external state or variables; it only relies on its input parameters.

Why They Are Important:

- Predictability: Immutability and pure functions lead to predictable behavior, making it easier to debug and reason about the code.
- Concurrency: Immutability allows safer concurrent programming since multiple threads can work with the same data without risking unintended modifications.
- Functional Programming: They are foundational concepts in functional programming, which promotes writing clean and maintainable code.

## Code Examples

Immutability Example

```typescript
// Using TypeScript to demonstrate immutability
type User = {
  readonly id: number;
  readonly name: string;
};

// Function to create a new user with an updated name
function updateUserName(user: User, newName: string): User {
  return { ...user, name: newName }; // Returns a new object instead of modifying the existing one
}

const user1: User = { id: 1, name: 'Alice' };
const user2 = updateUserName(user1, 'Bob');

console.log(user1); // Output: { id: 1, name: "Alice" }
console.log(user2); // Output: { id: 1, name: "Bob" }
```

Pure Function Example

```typescript
// A pure function to calculate the sum of two numbers
function add(a: number, b: number): number {
  return a + b; // Always returns the same output for the same inputs
}

console.log(add(2, 3)); // Output: 5
console.log(add(2, 3)); // Output: 5 (same inputs, same output)
```

### Key Parts of the Code:

- In the immutability example, the updateUserName function creates a new user object using the spread operator (...) without modifying the original user1 object.
- In the pure function example, the add function consistently returns the same result for the same parameters without modifying any external state.

## 3. Practical Use Case

### Use Case: State Management in React

In state management libraries like Redux, immutability is essential. When the state is immutable, it becomes easier to track changes and manage the application state predictably.

```typescript
type State = {
  users: User[];
};

// Reducer function that returns a new state instead of mutating the existing state
function userReducer(
  state: State,
  action: { type: string; payload: User }
): State {
  switch (action.type) {
    case 'ADD_USER':
      return { ...state, users: [...state.users, action.payload] }; // New state created
    default:
      return state; // Returning the current state if no action matches
  }
}
```

In this example, the userReducer function is a pure function that takes the current state and an action to produce a new state without modifying the existing state.

## 4. Common Mistakes and Best Practices

### Common Mistakes

1. Mutating Data: Forgetting to create copies of objects or arrays can lead to unintended side effects, making code harder to debug.
2. Using Non-Pure Functions: Functions that modify external state or rely on global variables can lead to unpredictable behavior.

### Best Practices

- Use Immutable Data Structures: Libraries like Immutable.js or Immer can help manage immutable data structures effectively.
- Prefer Pure Functions: Always strive to write pure functions where possible. This enhances reusability and makes testing easier.
- Leverage TypeScript Features: Use TypeScript’s readonly modifier and other type features to enforce immutability in your code.
