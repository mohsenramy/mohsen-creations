# Closures & Scopes in TypeScript

## 1. Core Concept and Significance

### Closures:

A **closure** is a function that "remembers" the environment in which it was created. This means it has access to variables from its outer scope, even after that scope has finished executing. In JavaScript and TypeScript, closures are commonly used for maintaining state across function calls without relying on global variables.

### Scope:

**Scope** refers to the current context of execution, where variables and functions are accessible. In TypeScript (and JavaScript), there are two main types of scope:

- **Global Scope**: Variables declared outside of any function or block are in the global scope.
- **Local Scope**: Variables declared within a function or block are in the local scope of that block.

Closures leverage the **lexical scope** of functions—meaning they can access variables defined in their outer scope even after that scope has returned. This is significant for creating more modular, functional, and maintainable code by encapsulating state and behavior.

## 2. Code Example

### Example 1: Function Scope & Block Scope

```typescript
function exampleScope() {
  let functionScoped = 'I am inside a function';

  if (true) {
    let blockScoped = 'I am inside a block';
    console.log(blockScoped); // Output: "I am inside a block"
  }

  // console.log(blockScoped); // Error: blockScoped is not defined
  console.log(functionScoped); // Output: "I am inside a function"
}

exampleScope();
```

### Closure with Private Variables

```typescript
function counter() {
  let count = 0; // Private variable

  return {
    increment: function () {
      count++;
      return count;
    },
    decrement: function () {
      count--;
      return count;
    },
  };
}

const myCounter = counter();

console.log(myCounter.increment()); // Output: 1
console.log(myCounter.increment()); // Output: 2
console.log(myCounter.decrement()); // Output: 1
```

In this example, count remains private, and only the returned functions (increment and decrement) have access to it, creating a closure.

### Here's a basic example of how closures and scope work in TypeScript:

```typescript
function createCounter() {
  let count: number = 0; // Local variable in the outer function

  // Inner function (closure) that modifies and returns the outer function's `count`
  return function () {
    count++; // Inner function has access to `count` from the outer scope
    console.log(count);
  };
}

const counter = createCounter();
counter(); // Output: 1
counter(); // Output: 2
counter(); // Output: 3
```

### Key Parts of the Code:

- `createCounter`: This is a function that creates and returns another function (closure).
- The inner function has access to the `count` variable, even though `createCounter` has finished executing.

## 3. Practical Use Case

### Use Case: Private Variables

Closures are often used to create **private variables** in JavaScript/TypeScript. This allows for data encapsulation and prevents direct access to internal variables.

Example of using a closure to create private variables:

```typescript
function BankAccount(initialBalance: number) {
  let balance = initialBalance; // Private variable

  return {
    deposit(amount: number) {
      balance += amount;
      console.log(`Deposited: $${amount}. New balance: $${balance}`);
    },
    withdraw(amount: number) {
      if (amount > balance) {
        console.log('Insufficient funds');
      } else {
        balance -= amount;
        console.log(`Withdrew: $${amount}. New balance: $${balance}`);
      }
    },
    getBalance() {
      return balance; // Access to the private balance variable
    },
  };
}

const account = BankAccount(100);
account.deposit(50); // Deposited: $50. New balance: $150
account.withdraw(30); // Withdrew: $30. New balance: $120
console.log(account.getBalance()); // Output: 120
```

### Why this is useful:

Closures allow for creating a bank account with a "private" balance. The balance can only be modified or accessed through the public methods (`deposit`, `withdraw`, `getBalance`), which protects the internal state of the account from being changed arbitrarily.

## 4. Common Mistakes and Best Practices

### Common Mistakes:

1. **Accidentally using global scope**: Variables in the global scope can be unintentionally modified by closures, leading to bugs.
2. **Memory leaks**: If a closure retains references to large data structures from an outer scope, it can lead to memory leaks.
3. **Misunderstanding asynchronous behavior**: Closures within asynchronous functions (e.g., `setTimeout`) may behave differently due to the event loop.

Example of a common mistake in asynchronous code:

```typescript
for (var i = 0; i < 3; i++) {
  setTimeout(function () {
    console.log(i); // Output will be 4, 4, 4 (incorrect behavior)
  }, 100);
}

for (let i = 1; i <= 3; i++) {
  setTimeout(() => {
    console.log(i); // Expected: 1, 2, 3. Actual: 1, 2, 3 (correct due to `let`)
  }, 1000 * i);
}
```

- In this example, using `let` works correctly because `let` creates a new scope for each iteration.
- If `var` were used instead of `let`, all `console.log` calls would print `4` because `var` does not create block scope.

### Best Practices:

1. **Minimize the use of closures**: Overusing closures can lead to hard-to-maintain code. Use them when necessary to maintain state or encapsulate functionality.
2. **Avoid memory leaks**: Be cautious of what your closure "closes over" (i.e., which variables it holds references to). Avoid holding references to large objects or unnecessary variables.
3. **Use block scope (`let` and `const`)**: Always prefer `let` and `const` to avoid issues with variable hoisting and unexpected behavior in loops.

By understanding and using closures effectively, you can write more modular, efficient, and safe code.
