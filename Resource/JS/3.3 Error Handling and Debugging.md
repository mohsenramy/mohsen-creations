# Error Handling and Debugging in TypeScript

## 1. Summary

**Error handling** is crucial in programming as it helps to identify and manage exceptions that disrupt the normal flow of an application. In TypeScript, error handling is typically done using `try-catch` blocks, allowing developers to handle anticipated exceptions gracefully. Furthermore, creating **custom error classes** provides more structured and descriptive error messages. TypeScript offers built-in type-checking support for error handling, which aids in developing more robust applications.

**Debugging** involves identifying and resolving issues within code. TypeScript supports debugging through tools like `node --inspect`, Chrome DevTools, and the VS Code Debugger. These tools enable developers to inspect code execution, set breakpoints, and evaluate variables, making it easier to pinpoint and fix issues.

## 2. Code Examples with JSDoc and Explanations

### 2.1 Using `try-catch` and Custom Error Classes

```typescript
/**
 * Custom error class for handling application-specific errors.
 * @class AppError
 * @extends {Error}
 */
class AppError extends Error {
  public statusCode: number;

  /**
   * Creates an instance of AppError.
   * @param {string} message - Error message
   * @param {number} statusCode - HTTP status code associated with the error
   */
  constructor(message: string, statusCode: number) {
    super(message);
    this.statusCode = statusCode;
    this.name = 'AppError';
    // Maintain proper stack trace (only available in V8 engines like Node.js)
    if (Error.captureStackTrace) {
      Error.captureStackTrace(this, this.constructor);
    }
  }
}

/**
 * Function to divide two numbers with error handling.
 * @param {number} numerator - The numerator for division
 * @param {number} denominator - The denominator for division
 * @returns {number | string} - Result of division or error message
 */
function divide(numerator: number, denominator: number): number | string {
  try {
    if (denominator === 0) {
      throw new AppError('Cannot divide by zero', 400);
    }
    return numerator / denominator;
  } catch (error) {
    if (error instanceof AppError) {
      console.error(
        `Error: ${error.message} (Status Code: ${error.statusCode})`
      );
      return `Custom Error: ${error.message}`;
    }
    return 'An unexpected error occurred.';
  }
}

console.log(divide(10, 2)); // Output: 5
console.log(divide(10, 0)); // Output: Custom Error: Cannot divide by zero
```

### Explanation

- **Custom Error Class**: The `AppError` class extends the built-in `Error` class, adding a `statusCode` property for additional context.
- **Error Handling in Functions**: The `divide` function checks for a zero denominator and throws an `AppError` if one is encountered.
- **TypeScript-Specific Benefits**: Type-checking ensures that any thrown error is caught and handled appropriately within the `catch` block. Using `instanceof`, we differentiate between custom and other errors.

## 3. Practical Use Case

### Scenario: Server-Side Error Handling for APIs

In a server-side application, such as an Express server, you can use custom error classes to represent different error types (e.g., `ValidationError`, `AuthenticationError`). This allows you to handle each error type differently, providing more detailed error messages for client responses and ensuring the server does not crash due to unhandled exceptions.

### Example

```typescript
app.get('/data', async (req, res, next) => {
  try {
    const data = await fetchData(); // This function might throw an error
    res.status(200).json(data);
  } catch (error) {
    if (error instanceof AppError) {
      res.status(error.statusCode).json({ message: error.message });
    } else {
      res.status(500).json({ message: 'An internal server error occurred.' });
    }
    next(error);
  }
});
```

## 4. Common Mistakes and Best Practices

### Common Mistakes

- **Overusing `try-catch`**: Use `try-catch` only where errors are expected. Unnecessary use can clutter the code and decrease readability.
- **Failing to Log Errors**: Always log errors to aid in debugging, especially in production environments.
- **Ignoring TypeScript’s Error Type**: TypeScript assumes `any` type for errors; use type narrowing (like `instanceof`) to differentiate between error types.

### Best Practices

- **Create Custom Error Classes**: This practice provides more context about errors and enables more granular handling.
- **Log Meaningful Error Messages**: Use logging libraries to ensure all error details are recorded, which is crucial for debugging.
- **Use TypeScript’s Type Checking**: Ensure proper type annotations and handle all possible error scenarios to avoid runtime issues.
