### Clean Code Practices in JavaScript/TypeScript

#### 1. Core Concept and Significance

**Clean code** refers to writing software that is easy to read, understand, maintain, and extend. It focuses not just on code that works but on code that is **readable**, **maintainable**, and **testable**. The goal is to ensure that others, or even your future self, can understand the code quickly and make necessary changes without introducing bugs.

Key principles of clean code include:

- **Readability**: Code should be easily understandable.
- **Modularity**: Code should be broken down into small, reusable functions or modules.
- **Maintainability**: Code should be easy to update, debug, or extend.
- **Extensibility**: Code should be designed in such a way that new functionality can be added without altering existing code.

#### 2. Code Examples and JSDoc

##### Example 1: Readable and Modular Function with Meaningful Names and Comments

```typescript
/**
 * Calculates the total price after applying a discount.
 *
 * @param {number} price - The original price of the item.
 * @param {number} discount - The discount percentage to be applied.
 * @returns {number} The final price after applying the discount.
 */
function calculateDiscountedPrice(price: number, discount: number): number {
  if (discount < 0 || discount > 100) {
    throw new Error('Discount must be between 0 and 100');
  }

  // Calculate the discount amount
  const discountAmount = (price * discount) / 100;

  // Return the final price after discount
  return price - discountAmount;
}

console.log(calculateDiscountedPrice(100, 20)); // Output: 80
```

##### Key Clean Code Principles Used:

- **Modularity**: The function performs a single task: calculating a discounted price.
- **Meaningful Names**: Variables and functions have clear and descriptive names (`discountAmount`, `calculateDiscountedPrice`).
- **Avoid Magic Numbers**: The discount percentage is passed as a parameter rather than hardcoded.
- **Validation**: Ensures the discount is within a valid range.
- **JSDoc for Documentation**: The function has a clear description, parameters, and return value documented.

##### TypeScript Built-in Support:

- **Type Annotations**: TypeScript ensures that values passed to functions match the expected types (`price` and `discount` as numbers), improving safety and maintainability.
- **Error Detection**: TypeScript helps catch potential issues like passing the wrong data type at compile time.

##### Example 2: Refactoring Large Functions and Implementing Encapsulation

```typescript
/**
 * Fetches user data and calculates user metrics.
 *
 * @param {number} userId - The ID of the user to fetch data for.
 * @returns {Promise<object>} The user data with calculated metrics.
 */
async function fetchUserDataWithMetrics(userId: number): Promise<object> {
  const user = await fetchUser(userId);
  const posts = await fetchUserPosts(userId);
  const metrics = calculateUserMetrics(user, posts);

  return {
    user,
    metrics,
  };
}

/**
 * Fetches the user's basic data.
 *
 * @param {number} userId - The ID of the user.
 * @returns {Promise<object>} The user data.
 */
async function fetchUser(userId: number): Promise<object> {
  // Simulated API call
  return { id: userId, name: 'John Doe' };
}

/**
 * Fetches the user's posts.
 *
 * @param {number} userId - The ID of the user.
 * @returns {Promise<array>} A list of user posts.
 */
async function fetchUserPosts(userId: number): Promise<object[]> {
  // Simulated API call
  return [
    { id: 1, title: 'Post 1' },
    { id: 2, title: 'Post 2' },
  ];
}

/**
 * Calculates user engagement metrics based on user data and posts.
 *
 * @param {object} user - The user data.
 * @param {array} posts - The user's posts.
 * @returns {object} The calculated metrics.
 */
function calculateUserMetrics(user: object, posts: object[]): object {
  const postCount = posts.length;
  const userScore = postCount * 10;

  return { postCount, userScore };
}
```

##### Key Clean Code Principles Used:

- **Refactoring**: Breaking down a large function (`fetchUserDataWithMetrics`) into smaller, more focused functions (`fetchUser`, `fetchUserPosts`, `calculateUserMetrics`).
- **Encapsulation**: Each function encapsulates a single task, making it easier to manage, debug, and extend.
- **Single Responsibility Principle (SRP)**: Each function is responsible for one thing, improving code maintainability.
- **Loose Coupling**: Functions do not depend on each other’s internals, allowing for easy modification without breaking other parts of the code.

#### 3. Practical Use Case

Clean code practices are particularly useful in **large-scale applications** where multiple developers are working together. Imagine you are developing a web application where users can manage their financial data. Without clean code practices, as the application grows, understanding and maintaining the codebase becomes increasingly difficult.

For example:

- **Readability**: You can make sure new developers can quickly grasp what functions like `calculateInterest` or `fetchAccountBalance` do just by looking at the function names and reading comments.
- **Modularity**: You can break down complex operations (e.g., fetching user data, calculating metrics) into smaller, independent functions to prevent duplication and make testing easier.
- **Encapsulation**: Each function should handle only one task, so changes to one part of the application do not cascade into other parts, avoiding bugs.

#### 4. Common Mistakes and Best Practices

**Common Mistakes:**

1. **Long, Complex Functions**: Functions that do too much are hard to test, maintain, and debug. Break them down into smaller, reusable components.
2. **Poor Naming Conventions**: Names like `x`, `y`, or `doSomething` don't convey meaning. Use descriptive names like `calculateInterest` or `fetchUserData`.
3. **Magic Numbers**: Hardcoding numbers (e.g., `100`) into the code can make it less flexible and harder to maintain. Use constants instead.

**Best Practices:**

- **Readability**:
  - Use **meaningful names**: Choose names that reflect the purpose of variables, functions, and classes.
  - Ensure **consistent formatting**: Maintain consistent indentation, spacing, and naming conventions.
  - Write **comments** to explain complex logic and use JSDoc for documentation.
  - **Avoid magic numbers**: Use named constants to improve readability and maintainability.
- **Maintainability**:

  - Implement **modularity**: Break down code into small, focused functions and modules.
  - **Encapsulation**: Group related data and behavior within classes or objects.
  - Practice **loose coupling**: Minimize dependencies between modules to improve flexibility and testability.
  - Follow the **Single Responsibility Principle (SRP)**: Each class or function should have a single, well-defined responsibility.

- **Extensibility**:

  - Follow the **Open-Closed Principle**: Make your code open for extension but closed for modification.
  - Use the **Interface Segregation Principle (ISP)**: Avoid creating large, monolithic interfaces. Split them into smaller, more focused interfaces.
  - Apply the **Dependency Inversion Principle (DIP)**: Depend on abstractions, not concretions, to promote loose coupling and testability.

- **Testing**:
  - Write **unit tests** to ensure each individual component works as expected.
  - Use **Test-Driven Development (TDD)**: Write tests before writing code to drive development and ensure correctness.
