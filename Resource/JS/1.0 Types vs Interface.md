### 1. **Concise Summary: Type vs. Interface in TypeScript**

Both `type` and `interface` in TypeScript are used to define the shape of an object, but they have different capabilities and usage contexts.

- **`interface`**: Primarily used to describe the structure of an object, it allows the declaration merging (extending multiple interfaces) and can be used for classes and object types.
- **`type`**: A more flexible way to define types, including unions, intersections, and other advanced types. It’s useful for creating complex types and can alias any valid TypeScript type (objects, unions, primitives, etc.).

Understanding the difference is key to writing clean, maintainable TypeScript code, as each has its strengths and weaknesses.

---

### 2. **Code Examples with Explanations**

#### Example 1: Basic Usage of `Interface` and `Type`

```typescript
// Example of Interface
interface Person {
  name: string;
  age: number;
  greet(): string;
}

/**
 * Example of using interface in a class
 */
class Developer implements Person {
  constructor(public name: string, public age: number) {}

  // Implementing the greet method
  greet(): string {
    return `Hello, my name is ${this.name}.`;
  }
}

// Example of Type
type Animal = {
  species: string;
  isDomestic: boolean;
};

/**
 * Function that takes an Animal type and returns a message.
 * @param {Animal} animal - The animal object with species and domesticity information
 * @returns {string} - A descriptive message about the animal
 */
function describeAnimal(animal: Animal): string {
  return `The ${animal.species} is ${animal.isDomestic ? 'domestic' : 'wild'}.`;
}

// Using the function with a valid Animal object
const myPet: Animal = { species: 'Dog', isDomestic: true };
console.log(describeAnimal(myPet)); // The Dog is domestic.
```

#### Explanation:

- The `Person` interface defines the shape of an object expected by the `Developer` class, which implements it and includes the `greet()` method.
- The `Animal` type is a flexible way to define a structure. The `describeAnimal` function takes this type and returns a descriptive string about the animal.

### 3. **TypeScript Built-In Support**

**Interfaces** and **types** are part of TypeScript’s core features. TypeScript supports features like:

- **Declaration Merging**: Interfaces can be merged, but types cannot.
- **Extending**: Both can extend each other (`interface` extends `interface`, `type` extends `type`, and `type` extends `interface`, but not vice-versa for interfaces).
- **Utility Types**: TypeScript has built-in utility types like `Partial<T>`, `Readonly<T>`, and `Pick<T>`, which can be used with both types and interfaces.

#### Example of Extending

```typescript
// Extending an interface
interface Employee extends Person {
  employeeId: number;
}

// Extending a type
type Bird = {
  canFly: boolean;
};

type Parrot = Bird & {
  color: string;
};

// Using the extended types
const john: Employee = {
  name: 'John',
  age: 30,
  employeeId: 101,
  greet: () => 'Hi!',
};

const myParrot: Parrot = {
  canFly: true,
  color: 'Green',
};
```

### 4. **Practical Use Case**

A common scenario for choosing between `type` and `interface` is when you need to model a domain in an application. 

- Use **`interface`** if you expect your data structures to grow, as interfaces support merging and are more suited for defining object shapes.
- Use **`type`** when creating union types, function signatures, or when flexibility is needed in combining multiple types.

For example, in a complex system where you need to define API response types and possibly extend them later:

```typescript
interface ApiResponse {
  status: number;
  message: string;
}

interface DataResponse extends ApiResponse {
  data: any;
}

// Type-based unions
type SuccessResponse = ApiResponse & { success: true };
type ErrorResponse = ApiResponse & { error: string };

type ApiResult = SuccessResponse | ErrorResponse;
```

### 5. **Common Mistakes and Best Practices**

#### Common Mistakes:
- **Overusing `type` for everything**: While `type` is flexible, overusing it can make code harder to maintain. For simple objects, `interface` is often better because it’s extendable.
- **Ignoring Declaration Merging**: Interfaces can be extended across multiple files or parts of a codebase, which can lead to accidental changes or confusion.

#### Best Practices:
- **When to use `interface`:**
  - If you need to extend or merge object shapes across the codebase.
  - When defining object models or working with classes, especially when expecting structure growth.
  
- **When to use `type`:**
  - For advanced type manipulation, such as unions, intersections, or mapped types.
  - When working with complex types like union of objects, primitives, or functions.

#### Best Practices for Combining Types and Interfaces:

```typescript
// Use interface for objects with a predictable shape
interface Car {
  brand: string;
  year: number;
}

// Use type for union and intersection
type Vehicle = Car | Bike;

interface Bike {
  model: string;
}
```

#### Key Takeaway:
For most objects, start with `interface`. Switch to `type` when more flexibility is needed (e.g., unions, intersections).

---

### 6. **Conclusion**

- **Interface**: Great for defining the shape of objects, works well with classes and supports merging.
- **Type**: Offers more flexibility with unions, intersections, and mapped types but lacks merging capabilities.
- Best practice is to use `interface` for object modeling and `type` for complex types, union types, or when flexibility is needed in type definitions.

Yes, you can include methods in `type` definitions in TypeScript, just like you can with `interface`. The method definitions within a `type` work similarly to how you define methods in an object type in an `interface`.

### Example of Including Methods in `type`:

```typescript
// Defining a type with properties and methods
type Vehicle = {
  brand: string;
  year: number;

  // Method to get the vehicle's age
  getAge(): number;

  // Method to get the full description of the vehicle
  getDescription(): string;
};

/**
 * Function that takes a Vehicle type and returns its description.
 * @param {Vehicle} vehicle - The vehicle object
 * @returns {string} - A descriptive message about the vehicle
 */
function describeVehicle(vehicle: Vehicle): string {
  return vehicle.getDescription();
}

// Implementation of the Vehicle type
const myCar: Vehicle = {
  brand: "Toyota",
  year: 2010,

  getAge(): number {
    return new Date().getFullYear() - this.year;
  },

  getDescription(): string {
    return `The ${this.brand} is ${this.getAge()} years old.`;
  },
};

// Using the describeVehicle function
console.log(describeVehicle(myCar)); // The Toyota is X years old.
```

#### Explanation:

- The `Vehicle` type includes both properties (`brand` and `year`) and methods (`getAge()` and `getDescription()`).
- You can define methods inside a `type` just like in an `interface`. In this case, the methods `getAge()` and `getDescription()` are implemented directly in the `myCar` object.
- The `describeVehicle()` function takes a `Vehicle` type and calls its `getDescription()` method.

### Conclusion:
Yes, you can include methods inside `type` definitions. The functionality is very similar to `interface`, but `type` offers more flexibility in combining types, such as with unions and intersections.

#### Practical Use Cases:
Including methods in `type` definitions is useful when you want to define objects that not only hold data but also perform actions based on that data. For example, defining service objects, models with behaviors, or any object that encapsulates both data and logic.
